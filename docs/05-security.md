# 安全与信任边界

## 数据分类

MVP 仅允许：

- 公开养老政策和办事指南
- 虚构用户、服务、时段和预约
- 模型、评测和性能元数据

禁止进入仓库、日志、测试数据或模型上下文：

- 真实姓名、电话、地址、身份证号
- 老年人的病史、用药和护理记录
- 真实密码和 API Key
- 生产 Cookie、Token 或数据库备份

## 信任边界

| 输入 | 信任级别 | 处理方式 |
|---|---|---|
| 浏览器消息和 context | 不可信 | 长度与结构校验，只用于检索和生成 |
| 模型输出 | 不可信 | 只能映射到允许的工具参数，不能直接写业务表 |
| 知识文档正文 | 不可信数据 | 不作为系统指令，不允许触发工具 |
| 浏览器 draftId | 不可信引用 | 按当前用户和数据库状态重新验证 |
| 浏览器价格、时段、用户字段 | 禁止 | DTO 拒绝未知业务字段 |
| Java 构造的 userId | 服务内可信 | 来源必须是已验证 JWT |
| 内部 API Key | 服务凭证 | 只证明调用来源，不能绕过业务校验 |
| 数据库服务、时段和价格 | 权威业务数据 | 确认事务内重新读取 |

## 认证与授权

- 密码使用成熟哈希实现，禁止明文或自制加密。
- JWT 有较短过期时间，不在 URL 或日志中出现。
- 管理员接口使用方法级或路由级角色校验。
- 用户资源查询必须同时包含资源 ID 和当前 `userId`。
- 登录失败信息不得区分用户名不存在或密码错误。

## 登录限流

MVP 使用单进程内存固定窗口：

- 键：规范化 IP + username
- 10 分钟最多 5 次失败
- 成功登录清除失败计数
- 到期记录定期清理
- 返回 429 和等待时间

只限制登录，不影响预约并发测试。多实例部署时迁移到 Redis。

## 内部接口

- Java 与 Python 通过 `X-Internal-Token` 互相认证。
- Token 由环境变量提供，不提交 Git。
- 比较使用常量时间方法。
- 内部路由不配置到 Nginx。
- Token 错误返回 401，日志只记录失败事件，不记录 Token。
- 内部调用仍必须校验用户存在、服务状态、草案归属和容量。

## 预约安全

- 最终确认只接收 `draftId` 和 `Idempotency-Key`。
- 草案必须原子从 `PENDING` 更新为 `USED`。
- `appointment.draft_id` 唯一。
- 容量使用条件更新，不先读后写。
- 草案、容量、预约和审计位于同一事务。
- 前端按钮禁用不是安全保障。

## 文件上传

上传校验顺序：

1. 管理员身份
2. 请求体总大小
3. 文件名规范化和扩展名白名单
4. 声明 MIME
5. magic bytes
6. 解析后的文本大小与空内容检查
7. SHA-256 去重

规则：

- 只支持 Markdown 与 PDF。
- 单文件最大 10 MB。
- 存储时使用服务端生成的文件名。
- 禁止相对路径和用户控制的落盘路径。
- PDF 必须以 `%PDF-` 开头；Markdown 按文本处理且限制编码。
- 解析失败不自动无限重试。
- 扫描件不调用 OCR，改为人工 Markdown。

## Prompt Injection

系统提示必须说明：知识文档与用户消息都是数据，不能修改工具、权限或系统规则。

工具层结构性保障：

- 只注册 `search_services` 和 `prepare_appointment`。
- 参数通过固定 schema 校验。
- 工具不能调用最终预约接口。
- 文档内容不得作为工具参数来源，除非与用户明确请求及权威服务 ID 匹配。
- Java 对所有参数重新校验。

至少保留 4 个测试：

1. 文档要求忽略系统规则并下单。
2. 文档要求泄露内部 Token。
3. 用户要求绕过确认并直接预约。
4. 用户要求把服务价格改为 0.01 元。

## 日志与错误

允许记录：Request ID、内部用户 UUID、资源 UUID、阶段、耗时、结果码。

禁止记录：密码、JWT、内部 Token、API Key、完整消息正文、完整政策文档、供应商原始错误体。

向浏览器返回稳定错误码；详细异常只在服务端日志中记录，并同样不得包含密钥。

## SSE 资源控制

- 设置上游连接和读取超时。
- 浏览器断开后取消 Java 订阅。
- Python 检测断开并取消模型流。
- 每个用户限制同时进行的对话流数量；MVP 可限制为 2。
- 对供应商 429 返回友好错误，不进行无限重试。
