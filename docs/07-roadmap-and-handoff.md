## 周 0：可行性闸门

### A. JD 映射，45 分钟

- 把 MaaS、Agent、Java、Vue、Python、SQL、安全、Docker 和 CI 映射到模块与证据。
- 固定 JPA，不引入 MyBatis。
- 固定 Redis 和 Kubernetes 不进入 MVP。
- 建立 README 骨架并记录当前状态。

### B. Python 自检，2 小时

- 建立独立虚拟环境。
- 跑通 FastAPI `GET /health`。
- 使用 curl 得到 JSON。
- 通过环境变量读取 API Key。
- 完成一次中文 Embedding 调用。
- 输出向量维度和耗时，不打印密钥。
- 为 FastAPI 和 Embedding 各留下一个最小测试。

判定：

- 绿色：FastAPI 与 Embedding 均成功，可以继续。
- 黄色：能运行但理解或测试不稳定；周 2 不做 LLM 相关性过滤和幻觉检查。
- 红色：FastAPI 未跑通；周 1 只做 CLI，周 2 前半段补 HTTP/FastAPI。
- 阻断：没有可用 Embedding 接口；先解决供应商和模型，不假装完成 RAG。

### C. 中文解析验证，75 分钟

- 选择 3–5 份真实成都养老政策资料。
- 记录标题、机构、日期、URL 和 SHA-256。
- 覆盖普通 PDF、表格/复杂排版和扫描件。
- 为每份文档决定自动解析或人工 Markdown。
- 按 7 道知识库内、3 道知识库外建立首批问题。

周 0 结束后只允许三个结论：按计划继续；Python 降级但保留 Java 主路径；文档统一人工 Markdown。

## 周 1：最小 CLI 基线，8 小时

- 评测集扩展为 14 道知识库内、6 道知识库外。

黄色状态只做向量阈值和引用存在性检查；Alembic 放 Roadmap。

## 固定砍项顺序

| 顺序 | 砍项 | 降级 |
|---:|---|---|
| 1 | Redis | MVP 已移除 |
| 2 | 手机端深度打磨 | 只保留基础响应式 |
| 3 | 丰富执行轨迹 | 只展示阶段文字 |
| 4 | RRF | 语义和关键词加权 |
| 5 | 独立幻觉检查 | 引用存在性、包含性和拒答规则 |
| 6 | 管理员上传 UI | Swagger/curl |
| 7 | LLM 相关性过滤 | 向量相似度阈值 |
| 8 | PDF 自动解析范围 | 人工 Markdown |
| 9 | 取消页面美化 | 保留正确事务和可用按钮 |
| 10 | CI Compose 冒烟 | 本地冒烟，CI 保留三端测试与构建 |

不可砍：唯一 MVP 路径、Java 预约事务、草案消费、幂等、防超卖、取消回补、引用或拒答、内部 Token和可重复测试证据。

## 简历交接纪律

- “100 并发”写成“并发竞争与防超卖测试”。
- “20 路 SSE”写成“流式连接稳定性与断连取消测试”。
- 不写生产级高并发或高可用。
- 只有存在命令、硬件说明和结果文件的指标才能进入简历。
- 计划、Roadmap 和未验证功能不能写成已完成。
