# 产品需求与范围

## 产品目标

CareAgent 是一个求职作品型 MVP，用于展示 Java 主业务系统与 Python AI 服务的集成。它面向老人及家属，回答公开养老政策和服务问题，展示可核验引用，并在用户明确确认后创建上门服务预约。

## 目标用户

### 普通用户

- 使用演示账号登录。
- 询问成都养老政策或服务。
- 查看引用原文与来源。
- 查看服务卡片并生成预约草案。
- 确认预约、查看预约、取消预约。

### 管理员

- 使用管理员账号登录。
- 上传 Markdown 或可解析 PDF 政策文档。
- 查询导入任务状态。

管理员服务项目 CRUD 不在 MVP。服务、时段和价格全部由种子数据提供。

## 唯一必须完成的用户路径

```text
登录
  → 提交政策或服务问题
  → 获得带引用回答
  → 查看服务卡片
  → 生成预约草案
  → 明确点击确认
  → 服务端重新校验并下单
  → 在“我的预约”中查看结果
```

该路径中的任何节点失败，都不能用额外页面或技术亮点补偿。

## 功能需求

### FR-01 登录

- 支持 `USER`、`ADMIN` 两类角色。
- 登录成功返回短期 JWT。
- 失败登录受单进程内存固定窗口限制。

### FR-02 政策问答

- 问题最大 1000 个 Unicode 字符。
- 有可靠资料时返回答案与至少一条引用。
- 无资料或医疗问题必须拒答。
- 引用包含文档标题、机构、来源 URL、章节或页码和原文片段。

### FR-03 服务推荐

- 根据区域、服务类别和日期查询种子数据。
- 返回服务名称、说明、服务区域、服务时段和当前价格。
- AI 只能调用只读服务查询接口。

### FR-04 预约草案

- Agent 选择服务与时段后，请 Java 创建草案。
- Java 从数据库读取服务、时段和价格。
- 草案绑定当前用户并设置过期时间。
- 草案不能直接扣减容量。

### FR-05 确认预约

- 浏览器只提交 `draftId` 和 `Idempotency-Key`。
- 服务端原子消费草案、重新校验数据、扣减容量和创建预约。
- 一个草案最多生成一个预约。
- 同一个幂等请求重复提交时返回第一次结果。

### FR-06 我的预约

- 用户只能查看自己的预约。
- 时间按 Asia/Shanghai 展示。

### FR-07 取消预约

- 只允许 `CONFIRMED → CANCELLED`。
- 取消与容量回补位于同一事务。
- 重复取消不能再次回补容量。

### FR-08 文档导入

- 支持 Markdown 和可解析 PDF。
- 单文件最大 10 MB。
- 校验扩展名、声明 MIME 和 magic bytes。
- 扫描 PDF 不开发 OCR，人工转 Markdown 并保留原件链接。

### FR-09 单次追问

- 首版支持单轮问答和最多一次追问。
- 前端最多携带上一组用户问题与助手回答。
- 不提供长期记忆或从数据库恢复完整对话。

## 非功能需求

- 数据库保证预约不超卖和容量不为负。
- 内部 API 不通过 Nginx 对外暴露。
- Java、Python 和 Nginx 传递同一 Request ID。
- 浏览器中断 SSE 后，取消 Java 与 Python 上游任务。
- 所有密钥通过环境变量提供并排除在 Git 外。
- 不保存真实老人资料、地址、电话或医疗信息。
- 所有评测和性能数字必须有可重复命令。

## 明确不做

- 医疗诊断、用药、紧急分诊
- 真实身份认证、短信、支付
- 护理排班、服务人员端
- 服务管理 CRUD
- OCR、语音、多模态
- Redis、Kubernetes、监控大盘
- 通用工作流或审计框架
- 多租户、长期记忆、自主下单

## 完成定义

MVP 完成必须同时满足：

1. 唯一用户路径可从浏览器重复执行。
2. 有资料时引用正确，无资料时拒答。
3. 一个草案不能通过不同幂等键创建两单。
4. 100 个并发请求竞争容量为 10 的时段时最多成功 10 个。
5. 取消一次只回补一次容量。
6. 20 路 SSE 连接测试与断连取消测试有报告。
7. Docker Compose 能启动完整演示环境。
8. README、API、评测和测试记录与代码一致。
